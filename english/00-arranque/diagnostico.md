# Diagnóstico: ¿dónde estás realmente?

## Resumen Ejecutivo

Tu nivel de inglés no es un número (A2, B1, B2) — es **una lista de cosas
que puedes o no puedes hacer bajo presión**. Este diagnóstico mide cuatro
habilidades por separado, porque casi todos los ingenieros hispanohablantes
tienen un perfil desbalanceado: leen a nivel C1, escuchan a nivel B1 y
hablan a nivel A2. Saber cuál es tu cuello de botella real evita que
pierdas meses estudiando lo que ya sabes.

## 🧒 Explicación para dummies

Un examen de inglés tradicional te da un número, como si tu habilidad fuera
una sola barra de progreso. Pero el inglés son **cuatro barras separadas**:

```
Leer      ████████░░  te sale fácil, llevas años leyendo docs
Escuchar  ████░░░░░░  entiendes al indio del equipo, no al de Texas
Escribir  ██████░░░░  sobrevives en Slack con Google Translate
Hablar    ██░░░░░░░░  ← aquí está tu problema real
```

Estudiar "inglés" en general es como optimizar un sistema sin haberlo
perfilado: gastas esfuerzo en la parte que ya es rápida. **Primero perfila,
después optimiza.**

## 🎯 Objetivos

- Medir tus 4 habilidades por separado, con pruebas de 2-3 minutos cada una
- Identificar tu cuello de botella real
- Elegir la ruta del libro que te corresponde

---

## 🧪 El test (10 minutos, sé honesto)

Puntúa cada afirmación: **0** = no puedo, **1** = con esfuerzo y errores,
**2** = fluido y sin pensarlo.

### Bloque A — Leer

| # | ¿Puedo...? | Puntaje |
|---|---|---|
| A1 | Leer un README de GitHub y entenderlo sin traductor | |
| A2 | Leer un stack trace + issue de GitHub y entender qué falló | |
| A3 | Leer un RFC o post de arquitectura de 2000 palabras sin cansarme | |

### Bloque B — Escuchar

| # | ¿Puedo...? | Puntaje |
|---|---|---|
| B1 | Ver un video técnico de YouTube **sin subtítulos** y seguir la idea | |
| B2 | Entender una llamada de Zoom con 4 personas hablando y solapándose | |
| B3 | Entender a alguien que habla rápido y con acento (Texas, Escocia, India) | |

### Bloque C — Escribir

| # | ¿Puedo...? | Puntaje |
|---|---|---|
| C1 | Escribir un mensaje de Slack de 3 líneas sin traductor | |
| C2 | Escribir un comentario de code review que no suene agresivo | |
| C3 | Escribir un email a un cliente/manager sobre un problema, con tono correcto | |

### Bloque D — Hablar

| # | ¿Puedo...? | Puntaje |
|---|---|---|
| D1 | Decir mi standup (3 frases) sin escribirlo antes | |
| D2 | Explicar cómo funciona un sistema que construí, 2 minutos seguidos | |
| D3 | Discrepar en una reunión y defender mi punto en el momento | |

**Suma cada bloque por separado** (0-6 cada uno). No sumes el total: el
total esconde exactamente lo que estamos buscando.

---

## 📊 Cómo leer tu resultado

| Bloque | 0-2 | 3-4 | 5-6 |
|---|---|---|---|
| **A (Leer)** | Empieza por vocabulario técnico | Normal en ingenieros | Ya está, no le dediques tiempo |
| **B (Escuchar)** | [Módulo 3](../03-oido-y-boca/entrenar-el-oido.md) es tu prioridad | 15 min diarios de listening | Solo mantenimiento |
| **C (Escribir)** | [Slack y Email](../02-ingles-de-trabajo/slack-y-email.md) | Trabaja el **tono**, no la gramática | Ya está |
| **D (Hablar)** | Kit de supervivencia + [shadowing](../03-oido-y-boca/shadowing.md) diario | Producción forzada 10 min/día | Prepara [entrevistas](../04-entrevistas/tell-me-about-yourself.md) |

> 💎 **Perla Escondida #2**: si tu bloque A (leer) es mucho más alto que el
> D (hablar) — el caso del 90% de los ingenieros — **no tienes un problema
> de inglés, tienes un problema de recuperación**. Las palabras están en tu
> cabeza, pero solo puedes recuperarlas de forma *pasiva* (reconocerlas al
> verlas), no *activa* (traerlas a la boca en 0.3 segundos). La cura no es
> aprender palabras nuevas: es **forzar la recuperación activa** de las que
> ya tienes, y eso solo pasa hablando y escribiendo sin mirar el texto.
> Es la diferencia entre tener el dato en S3 y tenerlo en Redis.

## 🏋️ Actividad — Fija tu meta en una frase

Escribe **una sola frase** con esta plantilla y ponla donde la veas:

> *"El [fecha, 30 días desde hoy] voy a poder ______ en inglés sin
> prepararlo antes."*

Ejemplos buenos (concretos y verificables):
- "...dar mi standup completo sin escribirlo antes"
- "...explicar la arquitectura de mi servicio por 2 minutos seguidos"
- "...responder *tell me about yourself* sin leer"

Ejemplo malo: *"...hablar mejor inglés"*. No es verificable, así que nunca
vas a saber si lo lograste, y lo que no se verifica no se sostiene.

## 📚 Diccionario Rápido

| Término | Qué significa |
|---|---|
| **Recuperación pasiva** | Reconoces la palabra cuando la ves/oyes |
| **Recuperación activa** | La traes a la boca cuando la necesitas |
| **Cuello de botella** | La habilidad más baja; la que limita todo lo demás |
| **Ruta** | El orden de temas recomendado según tu perfil |
