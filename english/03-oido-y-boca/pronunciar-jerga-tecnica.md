# Cómo se pronuncia la jerga técnica (150 términos)

## Resumen Ejecutivo

Hay una categoría de vocabulario donde tu error se nota más que en ninguna
otra: las palabras técnicas que escribes todos los días pero nunca has oído
pronunciar. Decir "ca-ché" en vez de "cash", "kiuiú" en vez de "kiu" o poner
el acento en la sílaba equivocada de *deprecated* produce un instante de
confusión en el oyente justo en la palabra clave de tu frase. Esta es la
lista de referencia, con la sílaba fuerte en **MAYÚSCULAS**.

## 🧒 Explicación para dummies

Aprendiste estas palabras **leyéndolas**, no escuchándolas. Así que tu
cerebro les asignó una pronunciación española por defecto. Nadie te corrigió
nunca porque los que te escuchan hablan español igual que tú.

El día que entras a una reunión con nativos, esa deuda técnica se cobra
toda junta.

**Cómo leer esta guía**: escrito en "español fonético", con la sílaba
acentuada en MAYÚSCULAS. No es fonética profesional; es lo que te hace
sonar bien en 10 minutos.

## 🔢 Símbolos, siglas y cómo leer código en voz alta

| Símbolo | Se dice |
|---|---|
| `_` | **underscore** |
| `-` | **dash** / **hyphen** |
| `/` | **slash** |
| `\` | **backslash** |
| `.` | **dot** (en URLs y archivos) |
| `@` | **at** |
| `#` | **hash** / **pound** (US) |
| `*` | **star** / **asterisk** |
| `()` | **parentheses** / "parens" |
| `[]` | **brackets** |
| `{}` | **curly braces** / "curlies" |
| `<>` | **angle brackets** |
| `!` | **bang** / exclamation |
| `?` | **question mark** |
| `:` | **colon** |
| `;` | **semicolon** |
| `=` | **equals** |
| `==` | **double equals** |
| `=>` | **arrow** / "fat arrow" |
| `&&` | **and-and** / "double ampersand" |
| `\|\|` | **or-or** / "double pipe" |
| `\|` | **pipe** |
| `~` | **tilde** |
| `^` | **caret** |
| `0` | **zero** (US) / "oh" al deletrear |

**Ejemplos de código leído en voz alta**:
```text
user_id            → "user underscore id" / "user id"
/api/v1/users      → "slash api slash v one slash users"
app.config.json    → "app dot config dot json"
GET /users/:id     → "get slash users slash colon id"
if (x != null)     → "if x is not equal to null"
i++                → "i plus plus"
2>&1               → "two redirect to and one" / "two to and one"
```

> 💎 **Perla Escondida #16**: cuando dictes algo crítico por voz — un ID, un
> nombre de branch, un hash — usa el **alfabeto fonético OTAN**:
> *"That's branch fix-slash-A-B-C: Alpha, Bravo, Charlie."* Los nativos lo
> hacen todo el tiempo y resuelve de golpe los pares que se confunden por
> teléfono: **B/V/P**, **M/N**, **D/T**, **S/F**, **G/J**, **E/I**. Bonus:
> es un contexto donde tu acento deja de importar por completo, porque
> estás usando un protocolo, no el idioma. Los que necesitas de memoria:
> **A**lpha, **B**ravo, **C**harlie, **D**elta, **E**cho, **F**oxtrot,
> **G**olf, **M**ike, **N**ovember, **P**apa, **S**ierra, **T**ango,
> **V**ictor, **W**hiskey, **Z**ulu.

## 🏋️ Actividades

### Actividad 1 — Las 20 peores (10 min)
Di en voz alta las 20 de la primera tabla, 3 veces cada una. Después busca
en YouTube "how to pronounce [palabra]" para las 3 que más te cueste
creer. Escuchar la versión real cierra el ciclo.

### Actividad 2 — Lee tu propio código en voz alta (10 min)
Abre un archivo tuyo y lee 15 líneas **en inglés, en voz alta**, incluyendo
símbolos. Es rarísimo la primera vez y es exactamente lo que harás en una
entrevista técnica o al hacer pair programming.

### Actividad 3 — Explica tu stack (5 min)
Di en voz alta, seguido: *"We run Kubernetes on Azure, with PostgreSQL for
the main database, Redis for caching, and Kafka for events. The CI pipeline
is Jenkins, and we monitor everything with Grafana."*

Sustituye por tu stack real y repítelo hasta que salga sin trabarte. Esta
frase la vas a usar en **cada** entrevista y en cada presentación de equipo.
